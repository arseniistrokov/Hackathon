# Как мы работаем

## Ветки
```
main  ← только стабильное, то что показываем. Merge из dev: Арсений или Никита.
 └─ dev  ← интеграция. Сюда идут PR из feat-веток.
     └─ feat/<ID>-<кратко>   одна ветка = один блок = один уровень. Пример: feat/D1-store-l0
```
- `feat/*` живёт **не дольше 4 часов**. Не успел — режь задачу, а не держи ветку.
- Имя ветки обязано начинаться с `feat/<ID>-` — по нему CI (`check-paths`) определяет разрешённые пути.
- Изменение контрактов, моделей, fixture: ветка `contracts/<что>` → PR в `dev`, одобряют Арсений **и** Никита.
- Один раз в клоне: `git config core.hooksPath hooks` (хук не даст закоммитить `.env`, модели, файлы > 5 MB).

## Цикл одной задачи
1. Открыл свой `docs/team/<Имя>.md`: там порядок блоков. Контракт — `docs/contracts/<ID>_*.md`, референсы — `docs/references/<ID>/`. Перед первым блоком — `docs/CONTEXT.md`.
2. Вставил контракт целиком в чат-нейронку (ChatGPT / Claude / Qwen). В контракте есть инструкция планировщика: она выдаёт доску из 5–9 коротких задач и дальше даёт задачи по одной.
3. Копируешь задачу CLI-агенту (Claude Code / Codex / Antigravity). Агент сам читает `AGENTS.md` из корня. Результат проверки шлёшь планировщику: `готово N` + вывод. Доску из его ответа сохраняешь в `docs/status/<ID>.md` — она едет в PR вместе с кодом.
4. **Посмотрел diff.** Агент тронул файл вне «Разрешённых путей» — откати это изменение.
5. Запустил тесты сам. Попросил агента временно сломать реализацию — убедился, что тесты краснеют.
6. Все задачи ✅ → планировщик даёт `ЗАДАЧА <ID>-QA`, агент проходит QA из контракта, пишет «QA» и «Отчёт» в `docs/status/<ID>.md` и ставит ✅ уровню в твоём `docs/team/<Имя>.md`. Открыл PR в `dev`, тот же отчёт — в чат.
7. Ждёшь ревью. Следующий уровень не начинаешь; можно взять L0 другого своего блока.

## Ревью и merge
| Чей PR | Первое ревью | Одобряет merge |
|---|---|---|
| Арсений | Никита | Никита |
| Никита | Арсений | Арсений |
| Паша | Арсений | Арсений или Никита |
| Дизайнеры | Арсений | Арсений |

- Одобрить свой PR нельзя. CI обязан быть зелёным (`ci`, `check-paths`, `size-check`).
- Ревью ≤ 15 минут на PR. PR больше 250 строк (без тестов) возвращается на разделение без чтения.
- Ревьюер проверяет: критерии приёмки закрыты тестами · пути не нарушены · модели контрактов не скопированы · есть откат на L0 · нет лишних зависимостей.
- После merge Арсений отмечает уровень в `docs/BLOCKS.md`.

## Сверки
Каждые 3 часа, 5 минут, по `docs/BLOCKS.md` и доскам `docs/status/*.md`: каждый показывает PR или экран, не рассказывает.
Нет PR за 3 часа → задача режется вдвое или уходит запасному из контракта. Без обсуждения.

## Если что-то сломалось в dev
1. Переключи блок на L0 переменной окружения в `.env` — демо снова живо.
2. `git revert` merge-коммита. Чинить — в feat-ветке, не в dev.
